## Content-Security-Policy

Generated by `scripts/write-headers.mjs`; `connect-src` is derived from
`VITE_ASSET_BASE` at build time (MVP §8: `connect-src 'self'` when every asset is
self-hosted).

Same-origin build:

```
default-src 'self'; script-src 'self' 'wasm-unsafe-eval';
style-src 'self' 'unsafe-inline'; img-src 'self' blob: data:;
connect-src 'self'; worker-src 'self' blob:; font-src 'self';
object-src 'none'; base-uri 'self'; form-action 'self';
frame-ancestors 'none'; manifest-src 'self'
```

With `VITE_ASSET_BASE` set (the Hugging Face model origin), `connect-src`
additionally allows `https://huggingface.co https://*.huggingface.co
https://*.hf.co` — the last two because HF redirects `/resolve/` to a `*.hf.co`
CDN, and a CSP does not follow a redirect's origin for free.

### Why each directive

| Directive | Value | Reason |
|---|---|---|
| `default-src` | `'self'` | Nothing loads unless explicitly allowed. |
| `script-src` | `'self' 'wasm-unsafe-eval'` | App + worker scripts are same-origin. Chromium blocks `WebAssembly.instantiate` under a bare `'self'`; `'wasm-unsafe-eval'` is the minimal keyword that permits WASM compilation (not JS `eval`). Found by running the app under the policy — see below. |
| `style-src` | `'self' 'unsafe-inline'` | `main.ts` sets element styles (e.g. hiding the download link) and `index.html` carries a `<style>`. No inline scripts exist, so this is the only inline allowance. |
| `img-src` | `'self' blob: data:` | Input preview and the transparent result use `blob:`; `data:` covers the favicon/harness. |
| `connect-src` | `'self'` (+ asset origin) | Only same-origin fetches unless a remote model origin is configured. |
| `worker-src` | `'self' blob:` | onnxruntime-web spawns pthread workers and a `blob:` worker from the origin. |
| `font-src` | `'self'` | No external fonts (MVP §8). |
| `object-src` | `'none'` | No plugins. |
| `base-uri` | `'self'` | Prevents base-tag injection. |
| `form-action` | `'self'` | No external form posts. |
| `frame-ancestors` | `'none'` | Clickjacking protection. |
| `manifest-src` | `'self'` | Web-app manifest. |

### The one real bug found and fixed

The first strict policy (`script-src 'self'`) **broke inference**: Chromium
refused `WebAssembly.instantiate` with

> Compiling or instantiating WebAssembly module violates the following Content
> Security policy directive … 'unsafe-eval' is not an allowed source of script.

The fix is the narrow `'wasm-unsafe-eval'` keyword, which permits only WASM
compilation. `'unsafe-eval'` (full JS eval) is **not** used. This is exactly why
MVP §8 says to configure the CSP *after testing actual runtime requirements*.
